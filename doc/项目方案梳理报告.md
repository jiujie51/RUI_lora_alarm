## 二、设备与服务器的约定（核心）

### 2.1 LoRaWAN 入网约定

| 约定项 | 设备侧（固件） | 服务器侧（SimulAlert LNS） |
|--------|-------------|--------------------------|
| 入网方式 | OTAA | OTAA |
| MAC 版本 | 1.0.3 | 1.0.3 |
| Class | B | B |
| 频段 | US915 | US915 |
| 凭证写入 | 生产烧录到 Flash ConfigStore | DevEUI/JoinEUI/AppKey 预先注册 |
| AppKey | **一机一密**（固件从 ConfigStore 读取） | 每台设备独立注册 |
| NVM 持久化 | 启用（掉电不丢会话） | — |
| Ping Slot | **不管**（服务器 Device Profile 配置） | 由服务器侧配置周期 |
| 入网重试 | 无限重试 + 指数退避 (10s→20s→…→900s) | 入网请求无限制 |
| 离线模式 | 入网期间 BLE/OLED/按键正常可用 | — |

### 2.2 FPort 分配约定

| FPort | 方向 | 内容 | 说明 |
|-------|------|------|------|
| 10 | 上行 | Badge 心跳 (CMD 0x00) | 必须与此 FPort 一致，服务器按此路由 |
| 11 | 上行 | Hub 心跳 (CMD 0x00) | 同上 |
| 20 | 上行 | 业务数据 (CMD 0x01/0x02) | 电量、按键事件 |
| 20 | 下行 | **全部下行**（单播+多播） | 通过 CMDID + group/room 区分 |

> ⚠️ Port 0/200/201/202 是 LoRaWAN MAC 层保留端口，设备固件不可占用。

### 2.3 应用帧格式约定（0xAA55 协议）

```
┌──────┬──────┬──────┬──────┬──────┬────────┬────────┬──────────┐
│ 0xAA │ 0x55 │ ver  │ ctrl │CMDID │length  │ CRC16  │  data    │
│  1B  │  1B  │  1B  │  1B  │  1B  │  2B BE │  2B    │   N B    │
└──────┴──────┴──────┴──────┴──────┴────────┴────────┴──────────┘
```

| 字段 | 长度 | 说明 |
|------|------|------|
| 帧头 | 2B | 固定 `0xAA 0x55` |
| ver | 1B | 协议版本，当前 `0x01` |
| ctrl | 1B | 控制标志，上行固定 `0x00` |
| CMDID | 1B | 指令 ID |
| length | 2B | 帧总长度（含帧头和 CRC），大端序 |
| CRC16 | 2B | CRC16/XMODEM (poly=0x1021, init=0x0000)，覆盖除 CRC 自身外全部字节 |
| data | N | 变长数据 |

**测试向量**：`{0xAA,0x55,0x01,0x00,0x00,0x08,0x00,0x03}` → CRC16 = `0x58C7`

### 2.4 上行 CMDID（设备 → 服务器）

| CMDID | 名称 | FPort | 触发条件 | data 格式 |
|-------|------|-------|---------|-----------|
| 0x00 | Heartbeat | 10(Badge)/11(Hub) | 每 5min | `{dev_type(1B), group_id(1B)}` |
| 0x01 | Power | 20 | 电量变化≥5% 且间隔≥5min | `{dev_type(1B), power_pct(1B)}` |
| 0x02 | KeyEvent | 20 | 按键确认 + BLE 扫描完成 | `{button(1B), motion(1B), rssi(1B), hub_mac(6B), lat(4B), lon(4B)}` |

**字段说明**：
- `dev_type`: `0x00`=Badge, `0x01`=Hub
- `button`: 按键 ID (Red/Blue/Yellow/Green), `0xFF`=静默定位
- `motion`: 保留（运动检测），当前填 `0`
- `rssi`: BLE 扫描到的 Hub RSSI，取绝对值（无符号）
- `hub_mac`: BLE 扫描到的最强 Hub 的 MAC 地址（6 字节），无 Hub 时填 `00:00:00:00:00:00`
- `lat/lon`: int32 大端，GPS 有效时填坐标，无效时填 `0x90000001` / `0x18000001`

### 2.5 下行 CMDID（服务器 → 设备）

| CMDID | 名称 | 方向 | 设备处理 |
|-------|------|------|---------|
| 0x03 | Code（告警） | 多播 | group_id + room_id 过滤 → alarm_sm_set() |
| 0x04 | Code Setting | 单播 | 更新 actuator 配置 → Flash 保存 |
| 0x05 | LED Control | 单播 | 直接控 LED |
| 0x06 | Buzzer Control | 单播 | 直接控蜂鸣器 |
| 0x07 | Vibration Control | 单播 | 直接控振动（仅 Badge） |
| 0x08 | LCD Content | 单播 | LCD 双行文字（仅 Badge） |
| 0x09 | LCD Line2 On/Off | 单播 | LCD 第二行开关（仅 Badge） |
| 0x0A | Clear Packet | 多播 | group_id + room_id 过滤 → alarm_sm_clear() |
| 0x50 | Set Group ID | 单播 | 更新 group_id → Flash |

### 2.6 多播过滤约定（应用层）

CMD 0x03 和 0x0A 通过**多播帧下发**，设备侧在应用层做双重过滤：

```
服务器下发多播帧 (CMD 0x03/0x0A)
  data = {group_id(1B), alarm_type或clear_type(1B), room_id(1B, 可选)}
              │
              ▼
  设备收到 → group_id 匹配?
              ├─ group_id & 设备 group_id == 0 → 不匹配，丢弃
              ├─ group_id = 0xFF → 全校广播，命中全部
              └─ 命中 → room_id 匹配? (如果 data 中有 room_id)
                         ├─ room_id = 0xFF 或 0 → 匹配全部房间
                         ├─ room_id = 设备 room_id → 命中
                         └─ 不匹配 → 丢弃
```

### 2.7 告警类型约定

| 优先级 | 类型 | 类型值 | 广播范围 | 触发源 |
|--------|------|--------|---------|--------|
| P0 | Code Red | 0x01 | 全校 (group=0xFF) | Red 按键 / Dashboard |
| P1 | Shelter | 0x08 | 全校 | Dashboard |
| P2 | Evacuate | 0x07 | 全校 | Dashboard |
| P3 | Secure | 0x06 | 全校 | Dashboard |
| P4 | Hold | 0x05 | 全校 | Dashboard |
| P5 | Medical (Blue) | 0x02 | Admin+Nurse 组 | Blue 按键 |
| P6 | Admin (Yellow) | 0x03 | Admin 组 | Yellow 按键 |
| P7 | All Clear (Green) | 0x04 | 全校 | Green 按键 / Dashboard |
| P8 | Normal | — | — | 默认空闲 |

### 2.8 设备身份约定

| 身份属性 | 长度 | 说明 | 设置方式 |
|---------|------|------|---------|
| DevEUI | 8B | 设备唯一标识 | 生产烧录 |
| JoinEUI | 8B | 入网域标识（全网统一） | 生产烧录 |
| AppKey | 16B | 入网根密钥（一机一密） | 生产烧录 |
| group_id | 1B | 角色 bitmask（Bit0=Admin, Bit1=Nurse...） | 服务器 CMD 0x50 远程设置 |
| room_id | 1B | 房间编号 | 服务器 CMD 0x50 / 生产烧录 |

## 三、网关配置（RAK7289CV2）

### 3.1 连接 SimulAlert LNS

RAK7289CV2 使用 **Basic Station** 协议连接 LNS：

| 配置项 | 值 |
|--------|-----|
| LNS 地址 | `wss://lns.simulalert.com:8887` |
| 协议 | WebSocket Secure (Basic Station) |
| 认证 | TLS 证书 / Token（由 SimulAlert 提供） |
| 频段 | US915 |
| GPS | **必须 Lock**（否则 Class B Beacon 不发送） |
| Class B Beacon | **必须 Enable** |

### 3.2 网关必须满足的条件

| 条件 | 原因 | 不满足的后果 |
|------|------|-------------|
| GPS Lock | Class B 需要全网时间同步 | 无 Beacon → 设备收不到下行 → Class A 退化 |
| 频段匹配 US915 | 与设备一致 | 收不到设备上行 |
| Beacon 周期 128s | LoRaWAN 标准 | 设备 ping slot 偏移基于此计算 |
| LNS 连接稳定 | 下行命令需实时转发 | 下行延迟增加或丢失 |

## 五、BLE 与 LoRa 协同（设备侧）

### 5.1 角色分工

```
Hub (固定)                          Badge (移动)
────────                            ────────
BLE: Peripheral Broadcaster         BLE: Observer Scanner
  广播 "ALARM_HUB"                    扫描 Hub 广播
  + MAC + room_id                    + 取 RSSI → 选最强
  + 间隔 2s                          + 报警时 4s 全速扫描

LoRa: Class B                       LoRa: Class B
  收下行 (CMD 0x03/0x0A)             发上行 (CMD 0x02)
                                     收下行 (CMD 0x03)
```

### 5.2 Code Red 触发全链路（设备视角）

```
Badge 按键确认 (Red 长按 5s)
  │
  ├─ BLE 扫描 4s → 收集 Hub RSSI → 选最强 Hub MAC
  │
  ├─ GPS 检查: 有效→填坐标, 无效→填无效标记
  │
  └─ LoRa 上行 CMD 0x02 (FPort 20, Unconfirmed)
       {button=Red, rssi, hub_mac, lat, lon}
              │
              ▼
         [服务器处理 → 多播 CMD 0x03]
              │
              ▼
         所有设备在 Class B Ping Slot 收到 CMD 0x03
         → alarm_sm_set(CODE_RED)
         → LED 红闪 + 蜂鸣 60s + 振动
```
